# Nexmux Model Console 管理控制面 测试方案（使用者视角）

> **测试对象**：Model Console 管理控制面（控制台 UI + Console 管理端点），运行于 `http://localhost:9011`（前端）/ `http://localhost:8082`（服务端）。
> **测试视角**：以 **控制台使用者**（平台管理员 / 配置运营 / 运营观察者）身份，按真实操作路径验证功能正确性、约束生效、数据与审计闭环、安全脱敏。
> **不在范围**：Model Runtime 数据面（Ingress 协议处理、选路算法、限流计数的内部实现）；底层 DDL/种子数据；性能压测基线。
>
> 配套文档：[功能说明书](./nexmux-functional-guide.md)、[功能页面清单](./nexmux-functional-catalog.md)。
>
> 执行结果与结论见 [测试报告](./nexmux-console-test-report.md)。

---

## 1. 测试目标

| 编号 | 目标 | 判定口径 |
|------|------|----------|
| G1 | 控制面核心配置闭环可用 | Provider→Model→Route→Client 全链路可配置、可发布 |
| G2 | 运行观测数据正确呈现 | 调用日志 / 用量 / 可靠性 / 成本与配置一致、口径标注清晰 |
| G3 | 通用约束生效 | 启停影响分析、删除保护、高风险二次确认、Code 不可改 |
| G4 | 安全要求满足 | Secret 不明文展示、日志/审计脱敏、接口匿名 401、前端权限不越权 |
| G5 | 体验与健壮性 | 空态回退、懒加载、分页、筛选、跳转联动、主题/语言 |

## 2. 测试环境与数据

| 项 | 值 |
|----|----|
| 前端 | `http://localhost:9011`（Pactor 动态页面；Next.js dev） |
| 服务端 | `http://localhost:8082`（Console；会话 cookie 鉴权） |
| 身份 | `admin / pactor123`（管理员，含成本/审计权限）；`guest / guest123`（访客/无权限） |
| 浏览器 | Playwright Chromium（无头），视口 1280×800 |
| 种子数据量（执行时快照） | Provider 47、Model 1672、Route 3、Client 3、调用日志 93、成本记录 65 |
| 时区/币种 | 控制台时区 `Asia/Shanghai (UTC+8)`、币种 `USD`、小数位 4 |

**测试数据命名约定**：新造对象统一以 `e2e-` 前缀，便于识别与清理；写操作优先复用/回退既有对象，避免污染。

**清理能力备注**：`provider-delete`、`route-delete` 已实现可清理；`model-delete`、`client-delete`、`client-template-delete` 服务端未落地（转发层回退 `{ok:true}`，数据不真删），相关测试点标注「需清理」。

## 3. 测试点约定

- **优先级**：`P0` 阻断级（核心闭环/安全）；`P1` 主要功能；`P2` 次要/体验。
- **结果**：`PASS` / `FAIL` / `BLOCKED`（环境或依赖缺失）/ `N/A`（当前版本未开放，仅验证降级表现）。
- **每个测试点记录**：实际结果、证据（页面文案 / 接口响应 / 截图）、缺陷描述与严重级。
- 未开放能力（标注「计划中」）仅验证：入口存在、明确提示、不产生错误或脏数据。

## 6. 执行策略与风险

- **执行顺序**：只读页面（G/D/O/S 读） → 配置写路径（P/M/R/C/T） → 调试与运行闭环（X/E） → 非功能与安全（N） → 回归。
- **写操作风险**：Model/Client/ClientTemplate 删除接口未落地，测试新造对象可能残留；统一 `e2e-` 命名并在报告中登记，可清理者（Provider/Route）测试后删除。
- **数据影响**：调试台会产生真实上游调用与费用；如无有效密钥/额度，调试类测试点可能 `BLOCKED`。
- **权限测试**：guest 账号权限受限，部分页面不可见，仅验证裁剪而非功能。
- **环境依赖**：服务端 8082 不可达时所有数据页退化为空态（属 T-G-17 预期），无法验证数据正确性，相关点记 `BLOCKED`。
