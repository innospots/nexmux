## 1. 产品概览

### 1.1 Nexmux 是什么

Nexmux 是企业级 **模型管理系统**。它把「哪些上游模型可用、对外如何暴露、谁能调用、调用产生多少用量和费用、一次请求为什么这么走」统一到一个控制台里管理。控制台本身 **不直接承接业务流量**，它负责配置与观测；真正按配置处理请求的是 **Model Runtime（数据面）**。

可以用一句话概括控制台的价值：

> **模型资源的统一管理入口、模型服务策略控制中心、运行观测入口和成本审计中心。**

### 1.2 五类核心能力

| 能力 | 对应问题 | 主要承载页面 |
|------|----------|--------------|
| **资产可管理** | 有哪些 Provider、逻辑 Model、上游绑定及能力 | 模型资产（供应商 / 模型） |
| **路由可配置** | 业务如何从请求路径映射到实际模型 | 模型路由（路由） |
| **访问可治理** | 谁可以调用、可以调用多少 | 访问治理（客户端 / 客户端模板） |
| **金额可追踪** | 一次调用对应多少用量、多少内部参考金额与供应商成本估算 | Model 定价 + 运行管理（用量 / 成本明细） |
| **运行可解释** | 一次请求为什么选了这个模型、失败在哪里 | 运行管理（调用日志 / 可靠性）+ 调试台 |

### 1.3 控制面与数据面

```text
┌──────────────────────────┐          ┌──────────────────────────┐
│  Model Console（控制面）  │          │  Model Runtime（数据面）  │
│  · 资产 / 路由 / 访问治理  │  发布 →  │  · Ingress 协议接入       │
│  · 定价 / 服务设置 / 审计  │  ← 观测  │  · 选路 / 限流 / 计量     │
│  · 运行数据只读展示        │          │  · 产生 Request/Usage/Cost│
└──────────────────────────┘          └──────────────────────────┘
```

- **Console 可写** 配置类数据（Provider / Model / Route / Client / 定价 / 服务设置）。
- **Runtime 产生** 运行类数据（Request / Usage / Cost / Metric / Route Trace / Health），Console 只读展示。
- Runtime 不依赖 Console 实时接口：路由与客户端策略需要 **显式发布** 才生效（见 [§6.5](#65-配置发布与运行版本)）。控制台故障不影响已在运行的数据面。

### 1.4 核心对象关系

```text
Client / AppKey
   │ Route 授权
   ▼
Route（逻辑模型 Alias + 入口 + 策略 + 候选模型）
   │ 选择逻辑 Model
   ▼
Model（能力 + 默认参数 + 定价）
   │ Provider Model Binding（供应商 + 上游模型 ID + 权重 + 倍率）
   ├── Provider A（Base URL + API Key）
   └── Provider B
                                  │
                                  ▼
                             Model Runtime
```

运行数据：`Request Log → Usage Record + Cost Estimate(pricing_snapshot) + Route Trace`。

## 2. 快速上手

### 2.1 访问与登录

- 浏览器打开控制台地址（本地默认 `http://localhost:9011`）。
- 匿名访问任意非公开路径会重定向到 **登录页**（`/login`）。
- 登录页文案：`RESTRICTED ACCESS` / **管理后台登录** / 「仅已分配平台审核角色的管理人员可以访问。」；输入 **用户名**、**密码** 后点「登录」。
- 登录成功后进入 **仪表盘**；右上角用户菜单可「退出登录」，退出后回到登录页。
- 演示环境内置账号：`admin / pactor123`（管理员）、`guest / guest123`（访客）。**演示账号仅用于本地联调，真实环境由外部身份系统提供。**

> 控制台不建设用户 / 角色管理页面：账号、组与认证由外部身份系统负责，控制台只做权限到页面/操作的映射。

### 2.2 界面构成

登录后进入标准管理端外壳，由三部分组成：

| 区域 | 内容 | 说明 |
|------|------|------|
| **左侧边栏** | 品牌（Model Console）+ 导航菜单 | 可 **收起 / 展开**；分组菜单点击展开子项 |
| **顶部栏** | 换肤、明暗切换、语言、用户菜单 | 见下 |
| **内容区** | 当前页面 | 面包屑 + 标题/副标题 + 页面内容 |

顶部栏操作：

- **换肤**：三套主题皮肤 —— **晨雾奶芙**（默认）、**苔径深林**、**宣纸墨韵**；切换即时生效并记住偏好。
- **明暗切换**：太阳/月亮按钮，缺省跟随系统深浅色。
- **语言**：`中文 / English` 切换（当前为演示：切换后提示「语言切换为 xx（演示：应用层桥接后整页生效）」）。
- **用户菜单**：显示登录用户名；含「个人中心（暂未开放，提示账号体系由平台统一管理）」与「退出登录」。

### 2.3 菜单总览

| 一级菜单 | 子菜单 | 页面路径 | 用途 |
|----------|--------|----------|------|
| **首页** | 首页 | `/` | 运营概览看板 |
| **模型资产** | 供应商 | `/providers` | 上游 AI 供应商端点与 API Key |
| | 模型 | `/models` | 对客户端暴露的逻辑模型 |
| **模型路由** | 路由 | `/routes` | 对外请求路径、协议与模型调度策略 |
| **访问治理** | 客户端 | `/clients` | 调用实例与 AppKey |
| | 客户端模板 | `/client-templates` | 预置路由 / 配额 / 限流的策略模板 |
| **运行管理** | 调用日志 | `/call-logs` | Gateway 请求历史 |
| | 模型用量 | `/model-usage` | 按模型与路由组的用量与成本 |
| | 供应商用量 | `/provider-usage` | 按上游供应商的用量与成本 |
| | 客户端用量 | `/client-usage` | 按客户端与 AppKey 的用量与成本 |
| | 供应商可用性 | `/provider-availability` | 可靠性分析 |
| **调试台** | 客户端调试 | `/client-debug` | 模拟业务侧真实调用 |
| | 模型调试 | `/model-debug` | 直连供应商模型验证 |
| **系统管理** | 服务设置 | `/service-settings` | 平台全局参数 |
| | 审计 | `/audit` | 管理操作留痕 |

> **详情 / 新增 / 编辑页不出现在菜单中**，经列表页跳转进入（例如 `/providers/:code`、`/models/:code/edit`、`/routes/:code`、`/clients/:code`、`/call-logs/:id`、`/costs/:id`、`/audit/:id`）。

### 2.4 角色与权限

控制台面向平台基础设施运维角色，按 **平台级操作能力** 划分权限，**不按 Tenant / Workspace 做数据隔离**。

| 默认角色 | 默认权限 |
|----------|----------|
| **平台管理员** | 所有模块的查看、创建、编辑、启停、发布、测试、密钥管理、成本查看、审计查看 |
| **配置运营** | 管理 Provider、Model、Route、Client 与访问策略；可测试、启停、发布；**不默认授予**密钥、成本、审计权限 |
| **运营观察者** | 运行数据与配置 **只读**；不默认授予成本、审计或密钥权限 |

权限类型：`View`（查看）、`Create`（新增）、`Edit`（修改）、`Enable/Disable`（启停）、`Publish`（发布）、`Test`（测试）、`Secret Manage`（密钥管理）、`Cost View`（成本查看）、`Audit View`（审计查看）。

`Secret Manage`、`Cost View`、`Audit View` 可作为独立权限授予或叠加，避免角色名称隐含敏感数据访问。菜单与页面按会话权限裁剪：无权限的菜单项不显示，直接访问无权限页面亦不加载。

## 3. 功能模块详解

### 3.1 首页 · 仪表盘

**路径**：`/`　**用途**：运营概览看板。

**页面结构**（三行）：

1. **核心概览 —— 4 张指标牌**
   - **请求量**：请求总数；副指标「活跃客户端数 · Token 总量」。
   - **成功率**：成功率 %；副指标「失败数 · 错误率」，可点「查看可靠性分析 →」跳可靠性页。
   - **平均响应时间**：平均延迟 ms。
   - **计费金额**：内部参考消费金额合计；副指标「平均每次请求参考金额」。
2. **趋势分析**：全宽走势图；Tab 切换 **请求 / Token / 费用 / 延迟**；说明「观察流量变化与异常峰值」。
3. **用量构成**：左右两个分布图，固定展示 **模型** 与 **客户端** 的请求量分布，各带快捷入口「查看全部 → 模型用量 / 客户端用量」。

**操作与筛选**：

- 右上角显示 **实时 RPM · TPM**，并提供「**↻ 刷新**」。
- 「**分析时间范围**」可按 `今天 / 近 3 天 / 近 7 天 / 近 14 天 / 近 30 天` 或自定义区间选择（UTC）。
- 图表点击可下钻到对应的用量页。

> 口径提示：金额为 **平台内部参考估算**，不生成客户账单 / 应收款 / 结算记录。

### 3.2 模型资产

#### 3.2.1 供应商（Provider）列表

**路径**：`/providers`　**副标题**：上游 AI 供应商端点。导入模板后，请填入你的 API Key。

**页面内容**：

- **搜索框**：按供应商名称 / ID / 端点 / 能力搜索，右侧显示「共 N 条」。
- **状态筛选 Chip**：全部 / 已启用 / 已停用 / 待填密钥 / 无密钥（含数量）。
- **类型筛选 Chip**：按供应商类型/品牌筛选（如 OpenAI、Anthropic、DeepSeek…）。
- **卡片网格**：首卡为「添加供应商」，其余为供应商卡片。
- **卡片字段**：图标、供应商名称（点击进入详情）、路由摘要（如「未关联路由」/「N 条路由 · M 条启用」）、密钥状态（`● 已配置 / ● 待填密钥 / ● 无密钥`）、能力标签；右上角悬停出现 **启停开关 / 编辑 / 填写密钥** 三个操作。
- **分页**。

**可执行操作**：

- **新建**：进入新增 Provider 页。
- **导入**：模板导入（当前提示「模板导入暂未开放」，建议改用新建或到详情页拉取模型）。
- **编辑**：进入编辑页。
- **填写密钥**：安全地补齐 API Key。
- **启用 / 停用**：二次确认。停用前展示 **影响范围**（该 Provider 下 Model 数量、启用 Model 数、被 Route Target 引用数），并提示「存在 ONLINE Target 引用时，建议先完成切换再停用」。

#### 3.2.2 新增 / 编辑 Provider

**路径**：`/providers/new`、`/providers/:code/edit`　**副标题**：定义供应商并配置上游连接与 API Key。

**页面分区**：

**① 基本信息**

| 字段 | 说明 |
|------|------|
| Provider Code | 唯一编码，**创建后不可修改** |
| Provider Name | 名称 |
| Provider Type | 商业 / 云服务 / 私有 / 自定义 |
| Default Protocol | 默认上游协议（OpenAI Chat Completions / OpenAI Responses / Anthropic Messages / Google Generative AI / Google Vertex AI / Azure OpenAI Responses / AWS Bedrock Converse Stream / Mistral Conversations / OpenAI Codex Responses / Pi Messages） |
| Status | 启用 / 停用 |
| Description | 描述 |
| Capability Extension | 能力扩展（JSON，折叠展开） |

**② 连接与凭证**

| 字段 | 说明 |
|------|------|
| Base URL | 上游接入地址 |
| Region | 区域（可选） |
| API Key | 掩码输入；保存后加密存储，**不回显明文** |
| Timeout (ms) | 请求超时 |
| Proxy | 代理（可选） |
| JSON 模式 | 切换为 JSON 编辑 |

**③ 能力扩展（Capability Extension）**：以 JSON 维护扩展配置。

**操作**：**测试连接**（保存前建议先测试 Base URL 与 API Key 是否有效）、**保存**、**取消**（编辑页另有「返回列表」）。连接测试结果展示是否成功、HTTP 状态、响应时间、Provider 错误、API Key 是否有效、测试时间；**测试失败不会自动修改配置**。

> 企业部署可用 **Secret Reference**（Vault / KMS 等）替代直接填写 API Key，与 API Key 二选一。

#### 3.2.3 Provider 详情

**路径**：`/providers/:code`。

**页头**：供应商名称 + 状态徽标 + `Provider Code`；操作 **编辑 / 停用（启用）/ 查看模型 / ···（删除等）**；概览区显示 **密钥状态、模型数量、默认协议、最后更新 / 操作人**。

**Tab**：

| Tab | 内容 |
|------|------|
| **基本信息** | Provider Code（创建后不可修改）、Provider Name、Provider Type、Default Protocol、Status、Description、Capability Extension、Created At、Updated At、Operator |
| **连接与凭证** | Base URL、Region、API Key、Timeout、Proxy、Last Test |
| **关联模型** | 该 Provider 下的模型；可 **拉取上游模型**（Model Code / Model Name / Provider Model ID / Model Type / Status），并 **创建 Model 草稿**（提示「已创建 Model 草稿（可去编辑补全定价与参数）」） |
| **引用关系** | 引用该 Provider 的对象 JSON（可复制），用于停用 / 删除前的依赖分析 |

#### 3.2.4 模型（Model）列表

**路径**：`/models`　**副标题**：维护对客户端暴露的模型。从目录导入，或新建空白模型。

**页面内容**：

- **搜索框**：按模型编码或名称搜索。
- **类型筛选 Chip**：全部 / 大语言模型 / 文生图 / 音频 / Embedding（含数量）。
- **厂商筛选 Chip**：按有效绑定的 Provider 筛选（含命中数）。
- **卡片网格**：首卡为「添加模型」（**导入** + **新建**），其余为模型卡片。
- **卡片字段**：模型名称 / Code、供应商图标、模型类型、上下文·输出（如 `1M · 128K`）、定价摘要（如 `$0.3 / $1.2 /M`）、路由摘要（`N 条路由 · M 条活跃` / 未关联路由）、状态；行内操作 **启停 / 编辑**。

**可执行操作**：**导入**（目录批量导入，当前提示暂未开放，可在 Provider 详情页逐个拉取）、**新建**、**查看**、**编辑**、**启用 / 停用**（停用时提示「存在活跃路由引用时，建议先完成切换再停用」）、**模型调用测试**（详情页）。

#### 3.2.5 新增 / 编辑模型

**路径**：`/models/new`、`/models/:code/edit`　**副标题**：定义对客户端暴露的模型：基本信息、默认执行参数与分档定价。

**Tab 分区**：

**① 基本信息**

| 字段 | 说明 |
|------|------|
| Model Code | 唯一编码，创建后不可修改 |
| Model Name | 展示名 |
| Model Type | 大语言模型 (LLM) / 文生图 (Image) / 音频 (Audio) / Embedding |
| Status | 启用 / 停用 |
| Provider / Provider Model Name | 主供应商与上游模型 ID（摘要） |
| 上下文窗口 / Max Tokens | 上下文长度、最大输出 Token |
| INPUT 模态 / OUTPUT 模态 | text / image / audio / video / file 等 |
| Tags / Description | 标签、描述 |
| 元数据 (JSON) | 扩展元数据，折叠展开 |

**② 默认参数（执行参数）**：`temperature`、`top_p`、`top_k`、`max_tokens`、`frequency_penalty`、`presence_penalty`、`reasoning_effort`（high / medium / low）、`seed`、`stop_sequences`、`response_format`（含 `json_schema`）。

**③ 定价**

- **标准价格（分档费率）**，单位 `$/1M`，按 **input_tokens** 命中档位：列为 `UPTO / INPUT / OUTPUT / CACHE READ / CACHE WRITE`；末行 UPTO 留空表示无上限。
- **命中规则**：取满足 `input_tokens ≤ UPTO` 的 **最小档位**；超出所有 UPTO 时用末行。
- **时段倍率**：适用日（每天 / 工作日 / 周末 / 周一至日）、时间范围（HH:mm，可跨日）、倍率（默认 1）。
- **Currency**：USD / CNY 等。
- 支持 **JSON 模式** 批量导入目录价。

**操作**：保存、取消；编辑页另有「删除模型」「返回列表」。

> 修改时段规则会提示：该变更影响采用默认价格时段倍率的 Provider Binding 成本估算与内部参考金额；**已发布的价格版本和请求快照保持不变**。

#### 3.2.6 模型详情

**路径**：`/models/:code`。

**页头**：模型名称 + 状态 + `code · 供应商 · 类型`；操作 **编辑 / 启用（停用）/ 模型调用测试 / 查看路由 / ···（导出、复制 Code）**。

**概览指标**：上下文 · 输出窗口、标准定价（$/1M）、当前定价版本、路由引用、最近更新。

**Tab**：

| Tab | 内容 |
|------|------|
| **基本信息** | Model Code、Model Name、Provider（主 + 共 N 个供应商模型）、Provider Model Name、Model Type、发布日期、上下文窗口、Max Tokens、INPUT/OUTPUT 模态与模态预览、Tags、Description、元数据、Status、Created/Updated At、Operator（含「编辑基本信息」入口） |
| **默认参数** | 上述执行参数 |
| **定价** | 标准价格、时段倍率、**版本历史**（Current / Historical / Future 与 Diff，只读） |
| **提供商** | 0..N 条 **Provider Model Binding**：Provider、Provider Model Name（上游 ID）、上游协议（可覆盖 Provider 默认）、权重、成本倍率 C、内部参考倍率 M、时段倍率、状态、连接状态 |

> **启用前提**：至少一个启用且可用的 Provider Binding；无绑定的 Model 可保存为草稿，但 **不能加入已启用 / 待发布的 Route**。

### 3.5 运行管理

> 本模块为 **只读观测**：调用日志、分维度用量、供应商可用性、成本明细。联调验证见「调试台」。

#### 3.5.1 调用日志（请求日志）

**列表**：`/call-logs`　**副标题**：查看 Gateway 请求历史。

- **筛选**：时间范围 (UTC)、状态、模型、供应商、协议、路由组、用户 Email、AppKey ID；「清除筛选」。
- **汇总**：总计 N 个请求；成功 / 错误 / 未完成 / 已取消 / 其他 状态分布。
- **表格列**：状态 · 时间、用户 · 系统、路由、标签、用量、成本 ($)、毛利 ($)。

**详情**：`/call-logs/:id`。

- **页头**：状态、端到端延迟、时间、`Route · Model · Provider` 摘要。
- **操作**：**在客户端调试复现**、**跳转客户端用量**、**跳转成本明细**、返回列表。
- **Tab**（11 个）：基本信息、调用主体、Ingress、路由结果、Upstream、性能、用量、成本、错误、**路由追踪**、**Prompt/Response**。
- 字段示例：`request_id`、`trace_id`、时间 (UTC)、状态、HTTP 状态码、协议、Route、Model、Provider、端到端延迟；调用主体含 Client / AppKey ID / Application / User Email / 客户端 IP / Channel / RouteTag；用量含 Input/Output/Total Tokens、Cache Read/Write Tokens；成本含 Pricing Snapshot；Ingress 含 Endpoint、命中 Alias；Upstream 含上游 Provider 与上游 message；性能含 TTFT。
- **Prompt/Response** 按「服务设置 → Prompt/Response 保存策略」展示；策略为「不保存」时提示「按平台策略，该请求未留存 Prompt/Response 内容。」

#### 3.5.2 模型用量

**路径**：`/model-usage`　**副标题**：按模型与路由组的用量与成本。

- 筛选：时间范围 (UTC)；Token 显示（紧凑 K/M/B ↔ 完整数字）。
- 「导出 CSV」；底部「范围合计 标准 / 计费 / 成本」。
- 列：模型、路由组、请求数、输入 Token、输出 Token、缓存命中率、标准、计费、成本、平均计费/请求、成功率、平均延迟、TTFT、平均上游、Token/秒、Failover 率、平均尝试。
- 无数据时显示「无数据」。

#### 3.5.3 供应商用量

**路径**：`/provider-usage`　**副标题**：按上游供应商统计用量与成本。列以 **供应商名称** 开头，其余指标同模型用量；支持导出 CSV、Token 显示切换。

#### 3.5.4 客户端用量

**路径**：`/client-usage`　**副标题**：按客户端与 AppKey 的用量与成本。列为 **客户端、AppKey ID** + 同上指标，并额外含 **配额用量**；支持导出 CSV。

#### 3.5.5 供应商可用性（可靠性）

**路径**：`/provider-availability`　**页面标题**：可靠性　**副标题**：供应商与路由质量。

三个区块：

1. **供应商质量** —— 按 Provider：供应商、请求数、成功率、错误、平均延迟、平均上游、Failover 率、平均尝试、标准、计费、成本。
2. **按模型对比供应商** —— 逻辑 Model + Provider Binding：模型 + 同上指标（近期错误单独展示）。
3. **近期错误** —— 时间 (UTC)、模型 / 供应商、错误；「查看全部错误日志」跳调用日志。

时间筛选同用量页（UTC）。无数据时各区块显示「无数据 / 暂无近期错误」。

> P0 调用日志已能显示单次错误与 Provider 连接状态；**Provider SLA 阈值与告警订阅为 P1**，当前版本未开放。

#### 3.5.6 成本明细

**列表**：`/costs`　**副标题**：按单次请求的实际成本与定价快照（命中档位 + 时段倍率）。

- 筛选：时间范围、Application、AppKey、Alias、Model、Provider。
- 列：Request ID、Time、Model、In Cost、Out Cost、Cache、Total、档位、倍率、Currency。

**详情**：`/costs/:id`。

- **证据链**：Cost → Pricing Snapshot → 调用日志（用量 Tab）→ 路由追踪 → Model 定价；可从本条记录逐级下钻。
- **定价快照（只读）**：`price_version`、命中档位（如 `UPTO ∞（无上限档）`）、档位单价、时段倍率、生效时间、Currency；提示「快照保存完整 pricing_snapshot，历史 Cost 不受后续改价影响」。
- **用量与费用拆分**：`input_tokens / input_cost`、`output_tokens / output_cost`、`cache_read_tokens / cache_cost`、Total；计算过程 `actual_price = tier_price × multiplier; Cost = Σ(usage × actual_price / 1M)`。
- 操作：查看调用日志、查看 Model 定价 / 版本历史、返回列表。

> 金额口径：`标准参考金额 = Σ(usage_component × 命中档位单价 × Model 时段倍率 / 1,000,000)`；`供应商成本估算 = 标准参考金额 × C`；`内部参考消费金额 = 标准参考金额 × M`。均为 **平台内部分析口径**，不代表应收 / 实收 / 对账金额。

### 3.6 调试台

> 两个页面均为 **Chat 对话式**：左侧对话记录，右侧配置或执行明细。
> **重要**：调试台在 Console 进程内模拟数据面链路，会产生 **真实上游调用与费用**；调试记录以 `source=DEBUG` 与真实流量区分。可在「系统管理 / 服务设置」关闭或限制日配额。

#### 3.6.1 客户端调试

**路径**：`/client-debug`　**副标题**：模拟业务侧真实调用，验证鉴权、路由与配额。

- 页面说明：选路与 Runtime 同一实现（策略 / 权重 / 优先级 / 粘性会话均生效）。
- **左侧 · 对话记录**：多轮对话与输入发送；「清空对话」。
- **右侧 · 调用身份**：客户端、AppKey（**Secret 仅会话内使用，不持久化**）、授权路由、Channel（如 WEB）、RouteTag、User。
- **执行明细**：发送后按轮次查看 **请求报文 / 返回报文**（格式化 / 复制）与运行摘要：状态、延迟、TTFT、命中路由组、Token (in/out)、Target、**查看调用日志**（Request ID → 调用日志）。
- 用于验证鉴权、路由命中、配额与限流，并支持从调用日志复现。

#### 3.6.2 模型调试

**路径**：`/model-debug`　**副标题**：直连供应商模型，验证连通性与效果。

- 页面说明：在 Console 进程内 **直连上游 Binding（不经过 Route）**。
- **左侧 · 对话记录** + 输入发送；「清空对话」。
- **右侧 · 调用身份**：供应商、模型、**连接测试**（用于连通性验证）；**System Prompt**；模型参数（temperature、top_p、max_tokens、reasoning_effort，按模型 Capability 动态显示）；Streaming、Tools（不支持 Function Calling 时提示「该模型不支持 Function Calling」）；**连接状态：未测试 / …**。
- 直连 Provider → Model，不经过 AppKey / Route 业务链路；对话用于效果验证。

#### 3.7.2 审计

**列表**：`/audit`　**页面标题**：审计日志　**副标题**：平台全部管理操作留痕（敏感数据脱敏显示）。

- 筛选：时间范围、操作人、操作类型、资源类型、Resource ID；「清除筛选」。
- 列：时间、操作人、操作、资源类型、Resource ID、IP；显示「总计 N 条记录」。
- **审计范围**：Provider / Model / Alias / Route / Client / Quota / RateLimit / Pricing / 服务设置 / AppKey。

**详情**：`/audit/:id`。

- Tab：**变更前 / 变更后 / Diff / 操作上下文**。
- 字段：操作人、时间、Request ID、IP。
- 支持变更前后对比与 Diff；**敏感数据脱敏**。

> 审计覆盖的操作包括（不限于）：新增 / 修改 Provider、修改 Provider 凭证、修改服务设置；新增 / 修改模型、模型上线 / 下线；修改 Route（含 Alias、Ingress、策略与候选 Model）、发布 / 回滚 Route 运行配置；修改 Provider Model Binding；修改授权 / 配额 / 限流；修改价格；创建 / 停用 AppKey、Secret Rotation。

## 4. 端到端使用流程

### 4.1 接入一个上游模型（P0 主流程）

```text
创建 Provider 并配置 Base URL / 凭证
      ↓
测试连接
      ↓
从上游拉取或手工填写 Provider Model ID
      ↓
创建逻辑 Model 与 Provider Binding
      ↓
配置能力、默认参数与可选参考价格
      ↓
测试 Binding 与 Model
      ↓
启用 Model
```

对应页面操作：

1. **模型资产 → 供应商 → 新建**：填写基本信息与连接凭证 → **测试连接** → 保存。
2. 进入 **Provider 详情 → 关联模型 → 拉取上游模型** → 勾选并 **创建 Model 草稿**（或到 **模型 → 新建** 手工创建）。
3. **模型详情 / 编辑**：补全基本信息、默认参数、定价，维护「提供商」Tab 的 Binding（权重、C/M、状态）。
4. 在模型详情点 **模型调用测试** 验证；通过后 **启用**。

### 4.2 配置并发布路由

```text
选择已启用逻辑 Model
      ↓
配置逻辑模型 Alias、Ingress（请求路径 + 协议）、候选与调度策略
      ↓
校验候选权重与协议兼容性
      ↓
模拟调用并检查路由结果
      ↓
保存草稿 → 显式发布
      ↓
Client 调试或业务调用验证
```

对应页面：**模型路由 → 新建路由** → 填写 ① 基本信息 ② 入口配置 ③ 模型与路由策略 → **模拟调用** → **保存草稿** 或 **保存并启用**。

### 4.3 创建客户端并授权

```text
新建 Client（或从模板创建）
      ↓
生成 AppKey Secret（仅展示一次）
      ↓
配置路由授权、配额与基础限流
      ↓
校验并发布 Client 访问策略
      ↓
用客户端调试验证鉴权与路由
```

对应页面：**访问治理 → 客户端 → 新建客户端 / 从模板创建** → ① 基本信息 ② AppKey ③ 路由授权 ④ 配额 ⑤ 限流 → **保存并启用**。

### 4.4 联调验证

**调试台 → 客户端调试**：选择客户端 / AppKey / 授权路由，发送消息，查看请求报文、返回报文与运行摘要（状态、延迟、TTFT、命中路由组、Token、Target）。

### 4.5 故障排查

```text
运行管理 → 可靠性 / 调用日志（定位 Request ID）
      ↓
调用日志详情：Ingress → 路由结果 → 选中的 Model 与 Provider Binding
      ↓
查看上游响应、延迟、用量、错误（错误 Tab）
      ↓
用客户端调试复现，或用模型调试直连验证上游
      ↓
检查 Provider 凭证、Binding 健康、Route 配置与发布版本
```

### 4.6 内部金额追溯

```text
成本明细（聚合或单次记录）
      ↓
pricing_snapshot（价格版本 + Binding + C/M + 生效时间）
      ↓
调用日志（用量 Tab）
      ↓
路由追踪
      ↓
Model 定价 / 版本历史
```

沿成本明细详情的 **证据链** 逐级下钻即可完成追溯。

## 5. 关键概念与术语

| 术语 | 含义 |
|------|------|
| **Provider** | 上游 AI 供应商类型 / 端点。承载 Base URL、Region、API Key、默认协议，并提供连接测试。 |
| **Provider Model Binding** | Model 内的可调用上游实例：`Provider + Provider Model ID`，附权重、成本倍率 C、内部参考倍率 M、时段倍率与状态。**不是独立菜单对象**。 |
| **Model（逻辑模型）** | 对路由与客户端暴露的统一能力定义：名称、能力、默认参数、内部参考价格。可绑定 0..N 个 Provider Binding。 |
| **Model Profile** | 附属于 Model 的可复用执行参数预设（**P1**，当前未开放）。 |
| **Alias（逻辑模型名）** | Route「基本信息」中的字段，标识对外暴露的逻辑模型名；不再单独维护列表。 |
| **Route（路由）** | 唯一用户可配置的路由单元，含入口（Path + 协议 + Operation）、策略与候选 Model。Entry / Policy / Rule / Pool / Candidate 均为其内部结构。 |
| **Client（客户端）** | 一个模型调用主体，持有 **AppKey** 用于 Runtime 入站鉴权。AppKey **不代表用户账户**。 |
| **Client Template（客户端模板）** | 预置路由授权 / 配额 / 限流的策略模板，**不含 AppKey**；基于模板创建客户端时才生成 AppKey。 |
| **AppKey** | 客户端调用凭证。Secret 仅在创建或轮换时展示一次，之后不可查看明文。 |
| **配额（Quota）** | 累计或周期性的调用量上限（Request / Token / Cost / Concurrent），分 Soft / Hard Limit。 |
| **限流（Rate Limit）** | 单位时间通过量控制（RPM / TPM / Concurrent），可细分到授权 Route，支持 Burst。 |
| **成本倍率 C** | Provider Binding 相对 Model 标准参考价格的供应商成本估算乘数。 |
| **内部参考倍率 M** | 内部参考消费金额乘数，**不代表客户账单**。 |
| **pricing_snapshot** | 每条金额记录保存的定价快照：价格版本、命中档位、Binding、C/M、币种与生效时间。 |
| **config_revision** | Route / Client 策略显式发布后产生的运行配置版本。 |
| **source=DEBUG** | 调试台产生的调用记录标记，与真实业务流量区分。 |

## 6. 通用交互与规则

### 6.1 状态与启停

- 通用对象提供 **启用 / 停用**；模型生命周期对象使用 `Testing / Verify / Online / Offline / Deprecate` 语义。
- 列表与详情页的启停开关都会弹出 **二次确认**，并展示影响范围。

### 6.2 删除原则

- 核心配置对象（Provider、Model、Provider Model Binding、Route、Client、Client Template）**存在有效引用时禁止直接删除**。
- 优先使用 **停用 / 下线** 而非物理删除；无引用并满足保留期后才允许删除。

### 6.3 敏感信息

- **AppKey Secret、Provider Secret、Credential Value 不得直接展示**；日志与审计中脱敏。
- API Key 保存后加密存储、掩码显示、不回显明文。

### 6.4 高风险操作确认

以下操作需二次确认，且确认框需展示影响对象：模型下线、Provider Model Binding 停用、Route 停用或发布、定价生效、API Client 停用、Secret Rotation、Hard Quota 修改、Rate Limit 大幅下调。

### 6.5 配置发布与运行版本

- **需要显式发布的运行时策略**：Route（含 Alias、Ingress、候选 Model、策略）、Client 路由授权、Client Quota / Rate Limit。
- 页面操作：保存 → 校验 → 发布 → 查看当前运行版本 / 历史版本 / 回滚。
- 发布粒度为「一个 Route」或「一个 Client」；**发布失败不替换当前运行版本**；发布成功产生 `config_revision`。
- Provider、Model 基础资料保存后立即更新控制面；启用 / 停用单独审计。

### 6.6 统一筛选上下文与跳转联动

- 运行分析类页面共享统一筛选上下文（时间范围、User / Application / AppKey、Channel / RouteTag、Alias / Model、Provider / Binding、Route），跨页跳转尽量保留筛选条件。
- 典型下钻链路：
  - Dashboard → 可靠性 / 用量 → 调用日志 → Route Trace → Binding；
  - 成本明细 → pricing_snapshot → 调用日志 → 路由追踪 → Model 定价；
  - 调用日志 → 在客户端调试复现。

## 8. 数据来源与对接说明

- 控制台为 **Pactor 动态页面**：页面 url、名称、导航、布局与页面 DSL 全部由 sitemap 对象驱动；页面数据经统一转发层直连 Console 服务端。
- **数据路径即契约**：页面数据源 URL（如 `/api/d/providers`、`/api/d/models`、`/api/d/stats-dashboard`）就是服务端接口路径。
- **空数据回退**：上游不可达、接口不存在（404）或返回非 JSON 时，GET 返回 `{}`、POST 返回 `{ ok: true }`，页面按空态渲染、不报错。
- **会话与鉴权**：转发层携带会话 cookie；匿名请求统一 401。前端权限只控制 UI，**接口侧仍必须鉴权**。
- **对接真实后端**：只需把前端环境变量 / 构建配置中的接口基准地址改为真实地址，页面 DSL 与转发层零改动。
